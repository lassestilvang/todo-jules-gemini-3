🚨 Severity: MEDIUM
💡 Vulnerability: The application relied solely on manual application-level transactions (`db.transaction`) to clean up related child records (subtasks, attachments, logs, labels) when deleting a parent task or list. If these transactions ever failed, were bypassed by new code, or if deletions happened directly via DB access, orphaned records would remain, leading to data inconsistency and potential application crashes when querying related data.
🎯 Impact: Orphaned database records, potential data leakage, and unhandled exceptions on the frontend if incomplete relational data is returned.
🔧 Fix: Configured `.onDelete('cascade')` and `.onDelete('set null')` explicitly on the relevant Drizzle ORM foreign key references in `src/lib/schema.ts` and generated the corresponding SQLite migration. This enforces referential integrity at the database engine level as a defense-in-depth measure.
✅ Verification: Ran `bun x drizzle-kit push` to apply the schema. Verified application builds successfully (`bun run build`), lints pass (`bun run lint`), and core functionality tests pass (`bun test`).
